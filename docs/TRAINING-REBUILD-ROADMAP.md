# Daily Ten 產品開發路線圖

更新：2026-10-20。本文件以目前產品為準；早期規劃保留在 Git 歷史。使用者已授權自主開發、獨立 QA 通過且 CI 綠燈後直接合併；外部運動專業審核不是此個人 MVP 的發佈條件。

## 五項需求與目前交付

| 使用者需求 | 已上線的行為 | 尚待完成或驗證 |
| --- | --- | --- |
| 看得懂動作 | 已移除訓練與求助中的火柴人；本機 AI 16 格影格可播放、暫停、慢速、逐格查看 | 逐動作補片與核對；完整影片仍為 0。實際數量以[覆蓋清單](../reports/exercise-media-coverage.md)為準，不把生成候選算成完成 |
| 求助不重頭開始 | App 內開啟示範即凍結步驟與倒數；關閉續練；重載恢復為暫停。Boss 測驗及未儲存結果亦有 checkpoint | iPhone 系統回收、長時間背景與真機音訊行為仍須實機驗證 |
| 時間合理 | 次數乘節奏、靜態停留、組間休息、器材轉換與準備分開計算；恢復日換組不再重複插入準備；雙側伸展中點提示換側 | 個別化負荷與生理效果未量測；估算不是動作品質判定 |
| 肌群刺激與進階 | 每週推／下肢／拉／恢復分配；週五短版下肢加拉力補強。九種精確工作組變式獨立判斷；兩個完整輕鬆回報日才加一次，最多基準加二。帶子用腳或另一手固定 | 無帶上背控制明示拉力有限，不能冒充負重拉。未自動調整每肌群週訓練量，核心與伸展未納入次數進階 |
| 路徑集中、容易回查 | 今日下一步、訓練目標卡、當前／下一動作、求助、結束回報與恢復入口集中。彈力帶標記會區分進階證據，今天換標記不改當堂目標 | 本批加入目標卡直達每組歷史，待獨立驗收及正式站驗證；尚無使用者研究證明操作效率 |

## 本批交付邊界

1. 每組回報歷史：實際／目標次數、感受、姿勢、疼痛與阻力標記；保留零次、負向及未完成課表的回報，不補算 XP 或達標。動作、近 28 天／全部篩選與分批載入；從目標卡直達並返回訓練。
2. 補足可用的動作示範。每張逐格檢查完整循環、左右側、鏡頭一致與名稱／文字相符；錯誤候選最多兩次修正後拒用。只登錄已接受的本機原圖，不以模糊別名增加覆蓋數。
3. 新檔加入離線快取；修復測試頁自動請求 favicon 所造成的假失敗，不放寬錯誤監控。
4. 獨立 QA、全套 CI、Jev 判斷、合併與正式站驗證一次完成。Jev 的摘要判斷與直接圖片檢視須分開記錄，兩者都不是完整運動驗證。

## 驗收與發佈

- 作者不能替代獨立 QA；資料／備份相容、求助續練、精確變式、時間、離線與手機版閱讀須有對應證據。
- QA PASS、repo／用語表／媒體檢查與完整 CI 綠燈後合併。正式網址轉送 GitHub Pages，合併後等部署並實測正式網址，不另稱已部署 Vercel。
- 發佈說明如實列出 AI 影格、缺片與完整影片數；不得稱為真人影片或所有需求已全部滿足。
- 真機項目僅留下機器無法驗證的 iPhone 系統回收、背景音訊及離線安裝體驗。

## 後續迭代順序

1. **媒體完成度**：已生成但序列不可靠的動作不硬上架；若生成與兩次修正仍失敗，改用使用者提供或具使用權的連續影片。先處理主課表缺片，再補測驗教學；不得以相似動作替代精確變式。
2. **實際訓練量**：以有效工作組回報建立每肌群週量與恢復間距，先顯示證據，再考慮調整組數／變式；不同帶子標記不混用。相關既有規則見[進階說明](./TRAINING-PROGRESSION.md)與[阻力標記](./BAND-RESISTANCE-TRACKING.md)。
3. **可用性與遊戲化**：用真實操作觀察驗證找課表、求助、續練與回查是否順暢；以出席、循序達標及週回顧回饋成長，不用 XP 鼓勵超量。

週頻率設計參考 [ACSM 2026 阻力訓練指引摘要](https://acsm.org/resistance-training-guidelines-update-2026/)，但每週達到頻率不等於已證明個人負荷或效果。BetterMe 男性廣告／網站與 Grit 的先前比較保留在產品研究文件；產品文案不承諾未經量測的成果。
